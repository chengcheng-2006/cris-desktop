# 验证方法与结果解释

本页让构建者明确每一种“通过”究竟证明了什么。它不是一份已执行的测试报告。历史执行范围见[支持矩阵](../SUPPORT_MATRIX.md)。

## 逐层验收

| 层次 | 典型证据 | 不能推出 |
| --- | --- | --- |
| 下载完整性 | 输入摘要与可信来源摘要一致 | 上游包无漏洞、无恶意内容 |
| 构建 | 脚本真实退出码为 0、目标文件存在 | 应用可启动、DS Bot 可用 |
| 结构 | `verify-artifact.sh` 的检查结果 | 完整路径扫描、严格签名、运行安全 |
| 依赖解析 | 在实际 DS Bot 导入位置找到预期版本 | 指定导出/API 存在 |
| 模块导入 | 在实际宿主解析环境中 import 成功 | Cordis 插件实际激活、UI 可用 |
| 插件激活 | 精确归属进程的启动诊断、宿主状态和无对应加载错误 | 前端资源加载成功 |
| 界面 | 正确应用中实际打开 DS Bot 入口及创建界面 | 模型调用成功 |
| 真实对话 | 用户授权的一次真实请求有响应 | 所有 provider、工具及多模态能力都正常 |
| 严格签名 | `codesign --verify --deep --strict` 退出 0 | Apple 公证、所有来源免 Gatekeeper 提示 |
| 源码脱敏 | 指定 SHA 的工作树、索引、历史与对象审查 | 安装包和运行数据也已放行 |

## 保留真实退出码

不要在经过 `tee` 或 `tail` 后读取 `$?`，再把它当成上游命令结果。建议在 Bash 中启用 `pipefail`，或直接重定向后立即记录状态。日志存到仓库外，分享前审查。

```bash
bash -euo pipefail -c 'bash build/verify-artifact.sh "$1"' _ "${OUT:?先填本次构建的实际输出目录}/Cris.app"
```

脚本没有要求结果必须永远是 11 项；未来新增检查会改变计数。关注具体检查、失败项、退出码与未覆盖范围，不把固定数字当验收目标。

## 最小只读信息

```bash
sw_vers -productVersion
uname -m
node -v
npm -v
git rev-parse HEAD
bash -n build/build-cris.sh
bash -n build/verify-artifact.sh
bash -n build/publish-gate.sh
```

以上命令属于环境/脚本信息采集，不会触发实际构建。不要为文档改动重新打包数 GB 应用，除非安装命令或实现发生变化需要验证。

## 签名与下载隔离

将 `INSTALLED_APP` 设为最终安装副本的真实路径；如果还未安装，就明确标注本次只验证输出产物，不能据此标记安装后验收。可先只读记录签名元数据，再执行严格校验：

```bash
codesign -dv --verbose=2 "${INSTALLED_APP:?先填本次实际验证的应用路径}"
bash -euo pipefail -s -- "$INSTALLED_APP" <<'BASH'
INSTALLED_APP="$1"
codesign --verify --deep --strict --verbose=2 "$INSTALLED_APP"
xattr -l "$INSTALLED_APP"
BASH
```

分别记录签名元数据、严格校验退出码和隔离属性。`Signature=adhoc` 不是严格校验的替代。没有 quarantine 也不能证明代码签名或运行安全。

## 进程与连接失败

- PID 采集失败时，不要把空 PID 传给 `lsof`；可能列出全系统连接，泄漏无关信息。
- 使用 `lsof` 多个选择条件时，核对是否需要 `-a` 才是交集；不能把未限定进程的端口当成目标应用端口。
- 沙箱拒绝 `ps`、本地连接或 Electron 启动时，单独记录环境限制；连接失败不证明服务未监听。
- 首页 HTML 不含 `ds-bot` 字样不证明前端未加载；插件可通过动态资源或注册机制装入。
- 包含某个字样也不证明该插件实际执行，应结合宿主与 UI 证据。

## 文件与隐私

可以检查状态文件是否存在，不要为证明插件启动而公开其内容。缺少某个默认路径只说明“该处未发现”，还需要核对实际数据目录、初始化时机及失败状态。

桌面控制的应用访问批准与 macOS 权限、进程沙箱是不同问题。被拒绝时不得通过禁用 Chromium 沙箱或批量修改权限来绕过；可以继续不依赖 GUI 的验证，最后明确记录 UI 未验证。

## 发布证据

建议报告包含：代码 SHA、输入摘要、环境、执行命令、退出码、逐层结果、尚未执行项、回滚方式。详细日志留在私有目录，公开只用必要的脱敏摘要。源码公开与二进制分发按[发布流程](../RELEASING.md)分别审查。
