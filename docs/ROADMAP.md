# 路线图与完成条件

本页列出方向与验收条件，不是交付日期或支持承诺。当前状态以[支持矩阵](../SUPPORT_MATRIX.md)为准。没有虚构完成百分比，也不因计划出现在这里就视为已实现。

## 第一优先：让公开构建真正启动 DS Bot

- 接收并审阅独立 Mac mini 修复代码，而不是只复述报告。
- 修复 DS Bot / Deep View 的宿主依赖解析，避免旧 peer 遮蔽。
- 保留其他插件需要的依赖，不批量替换整棵用户依赖目录。
- 新建 profile 和已有旧 peer 的 profile 都能加载；移动应用后仍能正确解析。
- 模块导入、真实插件激活、DS Bot 入口与创建界面分别通过。
- 对既有应用和个人数据可回滚；无密钥条件下仍能验收界面。

**完成条件：** 可获取的具体提交、可复现环境与上述逐项证据，经过独立脱敏审查；不能只凭构建脚本退出 0 放行。

## 第二优先：构建安全与严格签名

- 在删除输出前明确检查输入/输出冲突及已有文件。
- 挂载清理只操作本次拥有的资源，避免强制卸载无关同名卷。
- 签名按实际嵌套代码与 entitlements 处理，严格校验失败必须阻断产物交付。
- 保留诊断与失败退出码，不将错误藏在 WARN、管道或被吞掉的异常里。

**完成条件：** 代表性新旧输出场景通过；严格签名验证有退出码证据；错误路径不会损坏输入应用或用户数据。

## 第三优先：版本与可复现性

- 固定完整依赖闭包及输入应用摘要。
- 明确宿主 API 与插件版本的兼容组合。
- 统一源码、构建、测试和分发所用的清单。
- 补充有实际运行记录的 CI 或机器验收流程；先有工作流，再展示徽章。

**完成条件：** 同输入版本得到已知一致的依赖图，跨机器能复现功能验收；字节级一致性另行测定。

## 后续候选

| 方向 | 进入条件 |
| --- | --- |
| 完整品牌与数据目录 | 应用身份、Electron 数据和 DSH_HOME 一起设计并验证，不仅改文件夹名 |
| Windows 适配 | 有可用构建环境与实机；明确路径、权限、更新和安装策略 |
| 新上游版本支持 | 对锚点、API 和插件组合逐版本验收 |
| 安装包 Release | 隐私、组件许可、严格签名及安装/卸载/回滚分别过关 |
| 自有更新服务 | 有实际服务、完整性与版本策略、失败回滚；不能使用占位 URL 宣称可用 |

## 当前不安排

- 单独重做一套首启模型配置向导：现有上游设置页作为入口。
- 购买签名或公证服务：当前未安排预算，也不把它作为模块修复的前提。
- 在文档中预先宣称支持任意模型、完全离线、生产可用或无提示安装。

未来重新评估这些方向时，先更新验收条件与支持矩阵，不需要为保持原计划而重复开发。
