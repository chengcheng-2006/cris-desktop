# 常见问题

## Cris、DSH、DS Bot 分别是什么？

DSH 是基础运行环境，dsh-desktop 提供 Electron 桌面应用，DS Bot 是带有 Bot 团队与聊天界面的插件。Cris 在这些上游组件上探索个人助手的打包与使用体验。本仓库目前公开打包脚本、配置模板和文档，不包含一套独立重写的 Runtime。

## 这是 DeepSeek 官方产品吗？

不是。Cris 是独立项目；dsh-desktop 也是社区项目。上游版权和许可证仍须保留，不能因输出应用改名而更改其归属。

## 能直接下载 Cris 安装包吗？

截至[支持矩阵](../SUPPORT_MATRIX.md)的核对日，仓库没有发布经过安装包分发审查的 Release。GitHub 的 “Download ZIP” 只是仓库源码归档，不是应用安装器。构建指引面向能接受当前限制的测试者；不承诺开箱即用。

## 为什么构建完成，DS Bot 仍不出现？

已经确认一种原因：npm 自动安装旧宿主 peer，DS Bot 找到了包，但找不到 `createSystemMessage` 导出。见[排障](TROUBLESHOOTING.md)。`PASS=11` 是局部产物结构检查，不能证明插件激活或 UI 已显示。

## 把 ds-bot 加进 bundles 就能修好吗？

不一定。故障实例的 bundles 原本就包含 `ds-bot`，包也存在。先读取真实异常；不要反复添加、重装或覆盖配置。包可解析、模块导入、插件激活是三个不同阶段。

## 是不是必须有 Magpie？

模板不预置 Magpie 或其他网关，也不要求使用特定网关。你可以按所用 DSH/provider 支持的方式配置自己的模型服务。没有网关配置不等于完全离线：下载、npm、模型请求及某些上游服务仍可能联网。

## 构建和使用分别要不要付费？

仓库脚本本身不收费。构建需要设备、网络、磁盘和上游组件。真实模型调用取决于服务商账户、额度与价格。正式 Developer ID 签名和公证所需资格由 Apple 决定，本项目当前不提供证书或付费服务。不要把模型费用与开源许可证混为一谈。

## 不公证能用吗？

可信的本机构建可能可以运行，但本项目没有保证所有机器免提示。下载隔离、严格代码签名和 Apple 公证是不同机制。必须单独验证嵌套签名；清除隔离属性不能修好失效签名，也不应作为通用修复建议。

## 可以删除旧 Cris，或把数据目录清空再装吗？

不建议拿删除数据当排障。先记录原应用、数据目录与配置，做仓库外备份。改名不代表独立数据；测试账户或经核实的隔离副本更适合验收。操作前参考[配置与数据](CONFIGURATION.md)。

## 为什么应用叫 Cris，内部进程仍叫 DSH Desktop？

当前 `--name` 只设置输出应用与镜像名称，没有完整重写 Info.plist、可执行文件名和 bundle identifier。名称变化不能证明产品身份或数据隔离已完成。

## Windows、Linux、Intel Mac 能用吗？

目前构建脚本只面向 macOS。上游 universal 输入包含 Intel 架构，不代表本项目已经通过 Intel 实机验收。Windows/Linux 构建未实现，详见[支持矩阵](../SUPPORT_MATRIX.md)。

## 为什么不直接用最新版上游？

后处理依赖固定锚点和 API，已核对输入是 v2.0.18。更新版本应独立适配和验收，不能去掉断言后继续构建。仓库也不以 npm 的可变 latest 标签作为兼容性承诺。

## 可以把本地修复报告当成仓库修好了么？

不能。本地试验必须接收实际代码、审阅 diff、完成新旧 profile 和 UI 验收，再通过源码公开审查。截图、报告或某台机器上的模块测试都不能替代可获取的修复提交。

## 可以上传整份日志让维护者看吗？

不要。日志、配置和截图可能含模型凭据、登录态、会话和设备信息。提供错误类型、包名、缺失符号、版本与脱敏复现步骤通常更有效，见[支持指南](../SUPPORT.md)。
