# 安全模型与信任边界

这是一份当前实现边界说明，不是安全认证。Cris 的源码发布扫描不等于应用可以处理任意不可信输入或获得任意系统权限。

## 信任对象

构建者需要信任输入应用、下载来源、npm 解析出的依赖、构建脚本和构建机器。使用者还需要理解模型 provider、开启的插件、外部工具及数据目录的权限。模板不含 key 并不能消除这些信任要求。

## 构建时会发生什么

- 复制和修改输入应用的资源，创建依赖树、暂存副本与 DMG。
- 默认访问 npm registry；获取上游发行包会访问 GitHub 及其下载服务。
- 清理部分扩展属性、尝试 ad-hoc 签名。
- 删除专用输出中同名应用、镜像及工作目录；可能强制卸载同名卷。

因此应使用专门、全新的仓库外输出目录，不把已有安装、源应用或个人文件作为输出。当前脚本不应被当成对任意输入路径都安全的通用安装器。

## 运行时数据和网络

运行时可能创建 profile、会话、存储、Bot 状态及凭据。模型服务、插件市场或其他上游功能可能访问网络，本项目未证明完全离线或没有任何遥测。禁用特定上游更新入口不等于阻断全部联网。

配置与凭据如何持久化取决于所用 DSH/provider。这里不作 Keychain、静态加密或所有密钥只在内存中的保证。不要把运行数据、完整日志或配置发到公开渠道。

## 桌面身份与隔离

`DSH_HOME`、Electron `appData` / `userData`、保存的数据目录选择、应用 bundle identifier 和单实例锁共同影响运行位置。仅改应用名字或只设一个环境变量不能证明隔离。

静态模块导入和 Electron 原生初始化还可能先于 JavaScript 路径设置。测试若涉及旧应用数据清理，应核对完整启动路径或使用更强隔离。未证明隔离时标为未验证，不把它包装成“完全不触及原数据”。

## 签名不是同一件事

1. 显示 `Signature=adhoc`：只说明签名元数据类型。
2. 严格校验通过：证明指定副本在该次检查中满足代码签名校验。
3. Developer ID 与 Apple 公证：独立发行身份和服务流程。
4. quarantine 与 Gatekeeper：下载来源、系统策略和用户批准机制。

清除 quarantine 不能代替严格验签或判断来源可信。公开脚本当前签名失败不会阻断，这个缺口需要明确保留在支持矩阵中。

## 发布闸门的边界

公开脚本只放通用规则，定向个人规则由仓库外词表提供。文本规则会有漏报与误报，也无法理解所有二进制、动态拼接或业务语义。

独立审查应覆盖工作树、索引、全历史、对象、提交身份、标签、文件名和链接。源码放行绑定 SHA；二进制还要检查生成内容和依赖许可，不能照搬源码结论。
