# 配置与本地数据

## 开始之前

本页描述当前配置入口和数据边界，不提供任何真实 key，也不承诺各家 provider 都已验证。当前公开构建还有 DS Bot 导入故障，先查看[支持矩阵](../SUPPORT_MATRIX.md)和[排障](TROUBLESHOOTING.md)。

构建本身不需要模型账户；真实模型对话需要用户自己的服务、可用余额或其他授权。Cris 不赠送模型额度，也不要求使用 Magpie。

## 模型设置

目标 DSH 版本带有模型设置界面。进入“设置 → 模型”后，按所选 provider 类型填写或选择：

| 信息 | 含义 | 常见误区 |
| --- | --- | --- |
| Provider / 协议类型 | 服务使用的 API 协议与适配器 | 兼容 API 端点不一定兼容所有工具或多模态行为 |
| Base URL | 服务提供的 API 基址 | 重复添加 `/v1`、混入具体请求路径、误填网页地址 |
| Model ID | 服务实际接受的模型标识 | 界面显示名称和 API ID 可能不同 |
| 凭据 | 该服务自己的访问凭据 | 不要写入 GitHub、模板或故障报告 |
| 模型能力 | 上下文、输出上限、工具/图片等声明 | 不要凭模型名称猜容量或能力 |

配置字段和存储方式由具体 DSH/provider 实现决定。本仓库不保证凭据一定放在 Keychain、一定加密或一定只存在环境变量里。需要安全评估时，应检查实际版本的存储实现，而不是根据字段名推测。

如出现“模型未配置”“无可用模型”提示，先验证设置和 provider 授权；不要把所有对话失败都归为 DS Bot 插件故障。

## 建议的首次使用顺序

1. 确认正确应用和数据目录，避免误开另一份 Cris/DSH。
2. 确认 DS Bot 插件实际加载、入口可打开。
3. 在本机界面配置一项自己有权使用的模型服务。
4. 如果主动进行真实请求，应先了解服务费用；发一条简短文本检查响应。
5. 再根据需要开启工具或多模态功能，逐项验证权限与结果。

本仓库没有提供自动填写凭据或独立首启向导。

## 模板里有什么

[模板清单](../profile-template/package.json)选择基础 DSH、web app 与 `ds-bot` bundle；[种子层](../profile-template/cordis.patch.yml)有效内容为空列表，不预置模型、网关或凭据。

当前构建脚本也以内联内容生成模板；修改仓库中的模板文件不会自动保证构建脚本同步采用。维护者必须核对两处是否一致，不要把模板目录误当成脚本唯一配置源。

## 数据目录的区别

典型布局示意如下；**不是要求用户创建这些文件**，实际位置可能受应用设置或环境影响：

```text
应用安装目录/
└── Contents/Resources/
    ├── app/                 # 桌面代码与内嵌依赖
    └── profile-template/    # 构建时生成的初始化模板

用户选择的数据根目录/
├── profiles/desktop/        # 运行时 profile、依赖和配置
├── sessions/                # 会话数据
├── storages/                # 其他运行数据
└── bot/                     # DS Bot 运行数据，视实际初始化结果而定
```

常见默认 DSH 数据根是 `~/.dsh`，但不能据此断言某个进程正在使用它。需要结合应用设置、启动路径与运行时证据确认。运行数据不是可以直接公开的“示例配置”。

## 备份、并排安装与迁移

- 在同机有多份安装时，先记录每份应用的名称、bundle identifier 和实际数据目录。
- 重命名 `.app` 文件夹不会自动隔离数据。
- 备份应保存在仓库之外的私有位置；先退出对应应用，再按实际布局备份。
- 不要整目录覆盖另一份 profile；不要为消除导入错误而批量删除宿主依赖。
- 旧 profile 是否需要迁移应基于实际代码与测试确定，当前没有可保证的自动迁移器。
- 不要通过删除 `~/.dsh` 来“恢复出厂设置”，除非已明确理解数据范围并完成可恢复备份。

## 可以安全地交给维护者什么

可以提供：操作系统/架构、Node/npm 版本、工具链提交 SHA、上游输入版本、包版本、错误类型与缺失导出名称、脱敏后的复现步骤。

不要提供：完整配置、凭据文件、环境变量全集、会话、记忆、数据库、完整日志或未检查的截图。具体报告模板见[支持指南](../SUPPORT.md)与[安全政策](../SECURITY.md)。
